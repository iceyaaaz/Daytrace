# 部署与备份

## 准备 Supabase

1. 打开 [Supabase 控制台](https://supabase.com/dashboard)，创建自己的组织和项目。创建时设置的数据库密码由你自己保存。
2. 进入项目的 **SQL Editor**，新建查询，复制 [`supabase/schema.sql`](../supabase/schema.sql) 的内容并运行。每个空项目执行一次。如果提示已有同名表，先核对项目和现有表。
3. 在 **Authentication** 的登录设置中关闭公开注册和匿名登录，保留邮箱登录。
4. 在 **Authentication → Users** 手动创建你的日记账号。如有 **Auto Confirm User** 选项，将其勾选。登录日迹使用这个账号。
5. 如果项目里只有一个日记账号，可在 **SQL Editor** 运行 [`supabase/seed-exercise-tags.sql`](../supabase/seed-exercise-tags.sql)，预置跑步、力量训练、散步、球类和瑜伽。若有多个账号，请登录日迹后在设置中手动创建所需标签。
6. 从 Supabase 项目的 **Connect** 获取 **Project URL** 和 **Publishable key**。这两个值分别对应 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY`。在本地填写后，重启开发服务器。

## 启用历史搜索（V2）

1. 打开连接到 V2 的 Supabase 项目，点击 **SQL Editor → New query**。
2. 打开 [search-records.sql](../supabase/search-records.sql)，复制全部内容，粘贴后点 **Run**。已有项目升级时执行这份文件即可。新建项目先执行上面的建表步骤。
3. 用测试账号登录，在「历史 → 搜索」输入一条虚构记录的文字，确认能找到它。

## 部署到 Vercel

1. 在 Vercel 控制台点 **Add New → Project**，导入你有权限部署的 GitHub 仓库。框架选 **Vite**，构建命令为 `npm run build`，输出目录为 `dist`。
2. 在 **Environment Variables** 中配置上面的项目网址和公开密钥，再点 **Deploy**。只提交空白的 [`.env.example`](../.env.example)，把 `.env.local` 留在本机。
3. 部署后打开 Vercel 提供的 HTTPS 网址。先用测试账号写一条虚构记录，再从另一台设备登录确认能看到。正式使用时可以单独配置自己的生产项目。
4. 向 Vercel 配置的生产分支推送改动后，平台会重新构建。手机添加到主屏幕的操作见[使用说明](../使用说明.md)。

[Vercel 的 Vite 部署说明](https://vercel.com/docs/frameworks/frontend/vite) · [环境变量说明](https://vercel.com/docs/environment-variables)

## 导出和恢复

- **导出日记**：进入「设置 → 导出全部数据」，保存 CSV。Excel 可直接打开；形似公式的文本会加保护符号，数据库里的内容仍按原样保存。
- **做完整备份**：要保留账号、标签设置和数据库结构，请在 Supabase 控制台检查备份能力，或按官方指南导出数据库备份。
- **恢复**：先在空白测试项目中恢复数据库并核对账号、标签和记录，再切换 Vercel 的两个环境变量并重新部署。只有 CSV 时，可以用 Excel 查看后手工补记。应用没有 CSV 导入入口。

[Supabase 数据库备份](https://supabase.com/docs/guides/platform/backups) · [备份与恢复操作](https://supabase.com/docs/guides/platform/migrating-within-supabase)
